# S3: Approval integrity (browser verification part)

## 2026-11-24: WebCrypto Ed25519 verification in a real browser (task 6.5)

- Question: can a browser verify signatures made with `node:crypto` over our canonical JSON?
- Command: `npm run typecheck` (builds `packages/core/dist`), then `node spikes/s3/browser-verify.mjs`.
  The script signs a payload with `generateApproverKey` and `signPayload`, serves a page from `http://127.0.0.1:<port>/` (a secure context), imports the built `webverify.js`, and reads the result with `--headless=new --dump-dom --virtual-time-budget=5000`.
- Browsers: Edge 158 and Chrome 158 (both headless, Windows).
- Outcome (verified): in both browsers a valid signature verified (`{ok:true}`), and the same signature over a payload with one changed field returned `BAD_SIGNATURE`. The payload included non-ASCII text, so canonical bytes matched across Node and browser.
- Code: `packages/core/src/webverify.ts` (`verifyPayloadWeb`, WebCrypto only, never throws). Node test: `packages/core/src/node/webverify.test.ts` (valid, tampered, bad key, non-integer payload).
- Not verified: Firefox and Safari. Non-headless mode. Browsers older than 158 (Ed25519 in WebCrypto is newer in some engines). Real approval records (no key exists yet, task 6.6). The page was served over loopback HTTP; a non-secure origin has no `crypto.subtle`, and `verifyPayloadWeb` returns `NO_WEBCRYPTO` there.
- Failed first attempt: the script used `execFileSync`, which blocked the event loop so the local server could not answer, and both browsers timed out. Fixed by using async `execFile`.
- Limit: the browser check detects modification of the pack, gate report, or lock only if the page also recomputes their digests. This spike checks the signature over a payload, not digest recomputation in the browser (SHA-256 via `crypto.subtle.digest` is not tested here).
- Verdict: **GO**. Browser-side verification is feasible, so the build-time fallback is not needed. No decision entry added.
- Next: task 6.6 is a human step. Run `keygen` and keep the passphrase private.
